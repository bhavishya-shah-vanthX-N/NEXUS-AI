STRUCTURAL CLEANUP

What Gets Replaced vs. What Stays & Evolves

A deliberate audit of the current browser prototype: eliminating sandbox workarounds while preserving the core architecture choices that make the platform transparent and fast.

REPLACE / REMOVE

Browser Workarounds → Native Engines

  • Browser Hardware Sandbox Probes RUST + C++ DAEMON

    Current: Restricted to WebGL renderer, FPS, heap, and battery APIs; OS blocks CPU%, per-core clocks, NPU load, and °C thermals.

    Replacement: Lightweight Rust collector (sysinfo + eBPF) with C++ hardware FFI (NVML, Qualcomm QNN, Windows PDH/WMI, Linux hwmon) streaming sub-second metrics via gRPC.

  • IndexedDB Tab-Local Storage (NexusAI_DB) TIMESCALEDB / CLICKHOUSE

    Current: Single-machine browser storage capped by local quota, lacking cross-device queries, compression, or retention policies.

    Replacement: Rust ingestion worker buffering to local WAL/SQLite during outages and batch-writing into TimescaleDB or ClickHouse with tiered downsampling.

  • Single-Thread JS Statistical Heuristics PYTHON ML + C++ ONNX

    Current: Univariate Z-scores, linear OLS, and t-tests in js/ai-engine.js cannot model multivariate hardware-thermal interactions.

    Replacement: Python analytics engine (scikit-learn, PyTorch, statsmodels) for drift & Remaining Useful Life (RUL), compiled to C++ ONNX Runtime / TensorRT for edge scoring.

  • UI Simulation Loop & Static Hardware JSON REPLAY HARNESS + GRPC DISCOVERY

    Current: Synthetic timers in telemetry.js and static device cards in gallery.js.

    Replacement: Deterministic Rust/Python fault-injection & trace replay CLI for QA, plus live mDNS / Kubernetes Device Plugin node auto-discovery.

KEEP & UPGRADE

Proven Design Foundations Worth Retaining

  • Explicit Data Provenance (inputMode) AUDIT INTEGRITY

    Strictly tagging every sample as DEVICE, SIMULATED, MANUAL, or IMPORT prevents test noise from polluting production ML training sets or paging on-call engineers.

    Upgrade: Promote inputMode into a first-class Protobuf enum and signed ingestion metadata field across the TSDB schema.

  • Unified Source → Metric → Threshold Model SCHEMA CONTRACT

    The structured source configuration (metrics, units, warning/critical bounds, direction-aware thresholds, sampling rate) already maps cleanly to real monitoring rules.

    Upgrade: Formalize as versioned YAML/JSON manifests and OpenAPI/gRPC contracts compatible with Prometheus & OpenTelemetry semantics.

  • Web Serial / Web Bluetooth Field Diagnostics ZERO-INSTALL LAB MODE

    Direct browser UART and BLE GATT pairing is genuinely valuable for field technicians debugging an ESP32, Arduino, or sensor node over USB without installing drivers.

    Upgrade: Keep as an optional "Direct Bench Diagnostics" mode alongside the persistent Rust/C++ fleet agent.

  • Statistical Inference Baseline & High-Legibility UI EXPLAINABILITY & UX

    Student’s t intervals, Welch shift tests, DPI-scaled Canvas charts, and the low-noise monochrome layout deliver clarity without dashboard bloat.

    Upgrade: Keep classical statistical tests as fast, explainable sanity guardrails next to Python deep-learning detectors, backed by WebGL-accelerated charting.

EXECUTION SEQUENCE

Four-Phase Evolution Plan

Incremental migration path from the live browser prototype to distributed Rust, C++, and Python enterprise services without breaking existing workflows.

PHASE 01 COMPLETED · LIVE

Browser-First Prototype & UX Foundation

Zero-dependency web platform proving the end-to-end UX, IndexedDB storage layer, Workspace CRUD, CSV/JSON portability, Web Serial/BLE/WS pairing, WebGL2 benchmarks, and pure-JS statistical inference.

  • 7-page monochrome operator interface
  • Source/metric builder & bidirectional threshold alerts
  • Student’s t CI/PI, OLS slope & Welch shift tests
PHASE 02 NEXT · RUST & C++ CORE

Native Edge Collector & Hardware Telemetry

Build nexus-agent in Rust with C++ FFI drivers to bypass browser sandboxes, unlocking real per-core CPU, GPU/NPU utilization, wattage, fan RPM, and thermal headroom at sub-second intervals.

  • Rust collector (tokio + eBPF + sysinfo) < 15 MB RAM
  • C++ FFI bridges for NVML, QNN/Adreno, ROCm & WMI
  • Local SQLite/WAL ring-buffer for offline edge resilience
PHASE 03 PLANNED · PYTHON & ONNX

Python ML Pipeline & C++ Edge Inference

Move analytics server-side into Python for multivariate forecasting and hardware-to-model correlation, compiling lightweight anomaly detectors to C++/Rust ONNX Runtime on edge nodes.

  • Python FastAPI/gRPC service (PyTorch, scikit-learn, Evidently)
  • Multivariate Isolation Forest & thermal-throttle RUL modeling
  • P50/P95/P99 model latency + hardware drift correlation
PHASE 04 FUTURE · ENTERPRISE SCALE

Multi-Tenant Fleet Control Plane

Harden NexusAI for multi-cluster enterprise operations with open observability protocols, columnar time-series storage, security governance, and automated incident routing.

  • TimescaleDB / ClickHouse + OpenTelemetry (OTLP) & PromQL
  • OIDC/SSO, RBAC, mTLS device certs & immutable audit logs
  • PagerDuty / Slack / Webhook Alertmanager + Helm charts

TARGET ARCHITECTURE

Post-Migration Multi-Engine Stack

Assigning each language to the layer where it performs best rather than forcing JavaScript to handle systems telemetry or heavy ML math.

EDGE COLLECTOR LAYER

Rust + C++ Agents

  • Rust (tokio, tonic, sysinfo): Memory-safe daemon, gRPC streaming, eBPF network/process probes, SQLite WAL ring-buffer.
  • C++20 FFI Plugins: Direct bindings to NVML, CUDA, Qualcomm QNN NPU SDK, DirectML/ROCm, and industrial Modbus/CAN buses.
  • Footprint Goal: < 1% CPU overhead and < 15 MB RSS memory per edge node.
INTELLIGENCE LAYER

Python ML + ONNX Runtime

  • Python (FastAPI, PyTorch, scikit-learn): Offline training of Isolation Forests, LSTM/Temporal Fusion forecasting & drift audits.
  • C++ / Rust Inference: Export trained models via ONNX for real-time edge anomaly scoring without Python GIL overhead.
  • Statistical Guardrails: Retain Student’s t intervals & Welch shift tests for deterministic, interpretable alerts.
STORAGE & CONTROL PLANE

TSDB + Enterprise Security

  • Time-Series Engine: TimescaleDB or ClickHouse with automatic 1s → 1m → 1h rollup policies and Zstandard compression.
  • Open Protocols: OpenTelemetry (OTLP), Prometheus exposition, WebSockets for live UI push, REST/gRPC APIs.
  • Governance: mTLS node identity, OIDC/SSO, role-based access control, and immutable alert audit logs.
PRACTICAL VALUE

What Turns NexusAI Into a Truly Useful Platform

Beyond visual graphs, four engineering capabilities determine whether operators actually rely on a monitoring tool every day.

01

Hardware-to-Model Correlation

When an edge vision or LLM model slows down, most tools only show API latency. NexusAI correlates P95 inference spikes directly with NPU clock drops, thermal throttling, or battery power-saving states on the same timeline.

02

Offline-First Edge Resilience

Real robots, factory gateways, and mobile laptops lose Wi-Fi/5G. The Rust agent keeps writing telemetry to a bounded local disk ring-buffer and seamlessly backfills missed windows once connectivity returns.

03

One-Click Lab Check + Fleet Scale

Keep the browser’s Web Serial / Web Bluetooth pairing for instant 10-second bench debugging of microcontrollers, while scaling Linux, Windows, and Jetson fleets via containerized Rust daemons.

04

Actionable Diagnostics Over Noise

Instead of flooding Slack with static threshold spam, combine hysteresis windows, Welch distribution shift tests, and Python anomaly root-cause summaries so every alert maps to a clear fix.
